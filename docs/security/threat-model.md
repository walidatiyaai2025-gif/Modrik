# P0 threat model

## Assets and trust boundaries

Canonical assets are student accounts, academic history, answers, attempts, progress, official curriculum, provider links, content-preparation archives, publication review/audit state, and administrative privileges. Trust boundaries exist at public clients/API, Admin/API, third-party identity providers, optional AI helpers, ZIP import, reviewed content publication, database/queue, and cPanel deployment.

## Priority threats and controls

| Threat | Default controls | Verification |
| --- | --- | --- |
| Account takeover / credential stuffing | Framework password hashing, one stable enumeration-resistant invalid-login shape, dummy-hash work for missing/provider-only accounts, hashed-context rate-limit keys, backend-owned opaque sessions, recent-auth gates, password-reset/change session revocation. | Auth login/rate-limit, reset/revocation, recent-auth and session lifecycle tests on SQLite/MariaDB. |
| Provider email auto-link / account confusion | `provider + stable subject` is authoritative; provider email is mutable metadata only. Verified-email collisions never auto-link and return `PROVIDER_LINK_REQUIRED`; explicit recent-auth link intents are required. A subject already owned by another user returns `PROVIDER_IDENTITY_CONFLICT`. | Google/Apple verified-email collision, explicit link and cross-account subject-collision tests. |
| Provider assertion replay or substitution | One-time state + nonce intents persist only hashes and expiry; callback validates provider, signature, issuer, audience, expiry, stable subject and nonce before consuming the intent. The default provider verifier fails closed until external configuration exists. | Invalid/expired intent, nonce/cryptographic assertion and configuration-pending tests; production provider verification remains owner-configured. |
| Apple relay / hidden-email profile duplication | Stable Apple subject, never relay email, is the binding key. Relay flag/email are metadata and a later login without email resolves the same linked MODRIK user. | Apple relay link followed by hidden-email login; user-count and stable-subject assertions. |
| Session/token database disclosure | Raw bearer, verification and recovery tokens are returned/delivered only at creation and persisted as SHA-256 digests; IP/user-agent context is HMAC-hashed. Expiry, one-time consumption and revocation are backend-authoritative. | Persistence assertions prove stored values differ from raw credentials; session/token revocation tests. |
| Fixture credential production fallback | Production Auth endpoints require `auth.production`; learning fixture bearer is considered only when fixture mode is explicitly enabled. Production middleware never falls through to the fixture token. | Fixture-off denial against both learning and production-session routes; production session tests. |
| Unsafe account deletion / orphan credential reuse | Recent-auth plus explicit `DELETE`; atomic logical deletion preserves referential user ID while tombstoning direct identity, disabling password auth, revoking sessions/tokens, consuming intents and scrubbing provider subject/email metadata. | Account deletion, old-login denial, session revocation and audit-event tests. |
| Horizontal authorization | Backend derives actor from session and scopes every resource query; opaque IDs are not authorization. Offline sync acknowledgement lookup is actor-scoped before any replay decision, and foreign attempt/question IDs collapse to `RESOURCE_NOT_FOUND`. | Cross-user API and mixed offline-batch tests. |
| Academic-history loss or cross-track bleed | User-row serialization, reset-only track changes, explicit context IDs on attempts/progress, archive markers, transition audit, and active-context read filters. | REQ-P0-002 lifecycle/replay/preservation tests. |
| Attempt manipulation | Every new attempt receives a fresh 256-bit server-generated seed; client seed/question selection/order/blueprint fields are rejected; eligible selection and order are backend-owned; source order is avoided for shuffled multi-question attempts; variable blueprint sets rotate when constraints permit; authoritative positions and question/grading/scope snapshots persist atomically. | AC-P0-002..005 property/integration/abuse tests on SQLite and MariaDB 10.11. |
| Question-bank mutation after attempt start | Attempt question snapshot contains prompt/public response order, private grading contract, maximum score, content version and metadata; attempt scope snapshot freezes curriculum node and blueprint version. Resume and grading never consult mutable correctness/marks/order from the live bank. | Mutate/retire source question and quiz after answer, then resume/submit against original snapshot. |
| Unsafe option randomization | Option shuffle defaults off and requires explicit question opt-in. Sequence/ordered/image-letter/all-none semantics fail closed to source option order even when opt-in is set. | Safe opt-in shuffle plus explicit-off, sequence, image-letter and all/none preservation tests. |
| Replay/duplicate offline writes | 1–100 bounded batches; per-operation opaque ID stored only as actor-scoped domain-separated HMAC; canonical request hash; permanent final acknowledgement; optimistic answer revision; independent operation transactions; atomic answer + redacted outbox + acknowledgement; changed-payload same-ID conflict cannot replace the original acknowledgement. Unexpected server failures roll back the operation reservation rather than recording false success. | Exact replay/no-new-revision, interrupted resume, changed-payload reuse, stale-revision isolation, cross-user concealment, acknowledgement redaction, SQLite and MariaDB 10.11 tests. |
| Malicious returned ZIP | Compressed and uncompressed byte, entry, file-count, and ratio limits; normalized relative paths; no symlinks/traversal/duplicates; exact manifest membership; media allowlist; per-file SHA-256; schema/binding/semantic validation; durable rejected state; staging before review/publication. | Traversal, Unix-symlink, compression-bomb, binding, hash, and semantic archive tests. |
| Unauthorized or stale official content | Admin/Content Team route guard; originating request/settings/schema/content-hash binding; deterministic dry-run; explicit approved review; immutable audit; existing Backend-owned academic-track requirement; no UGC promotion; no synthesized board/syllabus values. Regenerated settings supersede stale work and stale access returns `PREPARATION_REGENERATION_REQUIRED`. | Student-role/UGC denial, origin mismatch, stale-settings precedence, missing-track/scope mismatch, review-decision and no-synthesis tests on SQLite/MariaDB. |
| Duplicate/partial official publication | Unique durable publication operation per preparation import; fixed publication-item set; immutable-ID/reference conflict checks; separate transactions for canonical draft import and official publication; exact replay returns existing operation; changed snapshot fails closed; failed transaction rolls back before sanitized recovery checkpoint; safe retry reuses durable operation. | Exact import/publication replay, changed-snapshot no-mutation, forced publication failure rollback/retry, deterministic supersession, audit/outbox count assertions. |
| Minor targeting or unsafe ads/community | Backend-owned placement/zone mapping; missing/invalid/stale/non-adult age assurance defaults off; versioned configuration defaults absent/off; global kill switch; immutable no-ad zones; no birth date/tracking profile; community disabled until P1 approval, no DMs. | AC-P0-011/012 precedence, cross-user scoping, audit-redaction, and config-off tests. |
| Paid-AI availability or student-data egress | Paid AI disabled by default; no P0 provider transport; learning core has no AI dependency; optional context is backend-allowlisted to locale and synthetic content references while identity, answers, progress, and credentials are prohibited. | AC-P0-015 complete-core test with outbound HTTP forbidden; disabled-boundary and context-minimization tests; repository contract validation. |
| PII/secrets leakage | Structured allowlisted logging, opaque identifiers, no raw answers/tokens/emails by default, secret scanning, synthetic fixtures. Auth security events contain opaque user/session IDs and optional HMAC context only; provider assertions, provider subjects, raw email/IP/user-agent and credentials are excluded. Offline acknowledgement rows contain hashes/codes/revision metadata only; assessment events may carry a SHA-256 seed fingerprint but never the seed or grading contract. Admin publication failures persist stable codes/fingerprints rather than raw exception text. | Auth persistence/security-event assertions, log/event inspection, sync persistence/outbox redaction tests, Admin failure/audit assertions, and repository scans. |
| Dependency/build compromise | Lockfiles, exact runtime pins, Composer/npm audits, dependency review, minimal CI permissions. | CI gates and periodic update PRs. |
| Availability/job duplication | Database queue, 1–500 bounded cron batches, per-event row locks/published recheck, stable event IDs, exponential retries, five-attempt cap, sanitized failure fingerprints, and explicit deferred/exhausted counters. | Overlap-safe completed replay, interruption/retry, backoff, exhaustion, redaction, and MariaDB worker tests. |

## Data minimization

Firebase is auxiliary and receives no canonical product state. Production authentication keeps the canonical MODRIK user/session/provider-link state in Laravel; raw session, verification, recovery, provider state/nonce and provider assertion material are never durable plaintext database fields. Provider email is metadata rather than the canonical identity key, and Apple relay status does not change account identity. Logical deletion retains only the user/tombstone and security history required for referential continuity; hard-purge and retention periods remain owner/legal inputs.

Optional AI is disabled by default, has no provider transport in P0, and receives no student PII by default. Its machine-readable allowlist/prohibition contract is `docs/security/optional-ai-boundary.yaml`. Offline synchronization does not duplicate raw answers into acknowledgement or outbox records and does not persist raw client operation IDs. Assessment seeds are cryptographic authority material, not client data: they are protected at rest and absent from API/outbox payloads; only a one-way SHA-256 fingerprint is retained for operational correlation. Correct-answer/grading snapshots remain server-private.

Admin publication stores the validated content snapshot required for deterministic review/import authority plus hashes, review metadata and immutable audit evidence. Operational failures retain only stable error codes and SHA-256 fingerprints, not raw exception text. Returned real curriculum content and rights evidence remain production-sensitive and must not be copied into issue comments/logs. Retention, backup, RPO, and RTO values remain owner decisions; until approved, code must support archival/deletion workflows without claiming a production retention policy.

## Security-release blockers

Production Google/Apple provider IDs, issuer/audience/callback configuration, Apple Team/Key/Services identifiers and private signing material remain external owner inputs. The default verifier therefore fails closed rather than simulating production trust. Exact real board/syllabus/version, curriculum/subject identifiers, content-rights evidence, legal controller/contact facts, age/ad/community activation, backup/retention/RPO/RTO, app identifiers/signing and production deployment inputs likewise require owner evidence. Their absence blocks only the affected production release path and must never be replaced with invented repository values.
